# 6노드 실제 vTPM 실험 결과 요약

2026-09-09 직접 실행에서 남은 공격·부하·반복 실험을 마쳤다.
현재 GCP 한도 내의 기존 6대(초기 3개 + 후발 3개)를 사용했다.
새 VM은 만들지 않았고, 초기·최소 난이도 4096 및 6/6 슬롯 승인 조건을
약화하지 않았다. 결과는 이 구성의 관측이며 보안 정리의 실증적 증명은 아니다.

| 항목 | 실제 관측 |
| --- | --- |
| 정상 등록·재시작·승인 누락 | 승인 대기 중 같은 요청 복구, 5/6 만료, 정상 새 요청 복구 확인 |
| TPM 응답 변조 | 다른 요청/체인 문맥과 손상된 서명의 첫 슬롯 승인 차단; 세 요청 모두 5/6으로 만료 |
| 진행 중 재전송 | 응답·승인을 새 nonce로 재전송한 실제 두 거래가 높이 5415에서 실패; 마감 5466 이전이며 5/6 불변 |
| 분리·재결합 | 실제 10블록 리오그, 이전 분기 승인 4개가 정식 등록 이벤트에 재사용되지 않음; 6노드 상태 수렴 |
| 초기 적격 비율 | 100%·50%·25% 각 3회, 총 9회에서 후발 등록 27/27 성공 |
| 정상 증거 검증 부하 | 두 검증 경로 × 작업자 1·2·4·8 × 3회 = 24회; 8,415,940회 반복 검증, 실패 0 |
| 실제 고비용 거부 부하 | 정상 정적 증거에 잘못된 주장 신원을 결속한 216건 접수 후 챌린지·승인 진행 0; 각 부하 구간에 블록 진행 |

확률 비교의 추가 6회는 첫 64블록으로 관측 길이를 맞췄으며, 매번 6개 노드의
높이 64 해시와 상태 루트가 일치했다. 모든 신원이 이 관측 구간 안에서
정식 블록을 생산했다. 최초 3회의 관측 길이는 서로 달라 별도로 보고한다.

## 확인된 한계

- 만료 후 정상 복구에는 **수동 재시작**을 사용했다. 자동 재시도 완료를 주장하지 않는다.
- 25%의 추가 두 실행에서 평균 블록 간격은 16.127초·11.159초,
  최대는 96초·101초였다. 초기 비율 이후 임계값 적응과 시간 완화가 작동한다.
- 정상 정적 증거 검증은 동시 작업자 1→8에서 처리량이 약 1215→1081회/초,
  실행별 p95 평균이 1.30→41.47ms로 변했다. 이는 실제 검증 함수의
  컴포넌트 부하 결과이지 정상 신규 가입의 종단간 처리율이 아니다.
- 부하 요청은 제한된 수량으로 순차 주입했으며 구간이 일부 겹친다.
  전체 네트워크의 포화 지점, 순수한 속도 효과, 전력 절감은 입증하지 않았다.
- 27/27은 확률 비교 9회에 속한 정상 가입 관측이다. 앞선 의도적 오류·만료를
  포함한 모든 등록 시도의 무실패율이나 독립 장치 27개의 표본이 아니다.

추가 실행의 깨끗한 공개 체인 DB를 다운로드하고 원격 해시와 비교했다.

키 보관 경로나 경로 탈출 항목이 없는지도 검사했다. 기존 DB는 삭제하지 않았다.
